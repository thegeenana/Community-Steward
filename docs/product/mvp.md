# Community Steward MVP

> Every contribution deserves a response.

## Outcome

For an installed repository, no new issue or pull request becomes silently stale. Maintainers see what needs attention, why, and the next humane action.

## First release journey

1. A maintainer installs Community Steward and selects repositories.
2. Signed GitHub events establish each contribution timeline.
3. Steward records first acknowledgement, human review and resolution time.
4. The attention queue highlights work approaching or exceeding repository policy.
5. A weekly report shows response health and recognises new contributors.

## MVP capabilities

- Secure GitHub App installation and webhook intake
- Repository acknowledgement and review targets
- Issue and pull-request contribution timeline
- First-time contributor identification
- Attention queue with deterministic reasons
- Repository health summary and weekly report
- Recommendation-only mode

## Explicitly later

- AI-generated review decisions
- Contributor ranking or productivity scoring
- Autonomous closing of community work
- Billing and marketplace plans

## Success measures

| Measure | Initial target |
|---|---:|
| Contributions acknowledged within policy | 90% |
| Contributions silently stale beyond policy | 0 |
| Median time to first human response | Under 24 hours |
| Webhook deliveries processed once | 100% |
| Automated destructive actions | 0 |
